# Forms and dashboard: layout specification

All forms are generated by `modBuildDatabase.CreateForms`. This document describes what that code builds, so you can adjust it in Design View or change the builder. Measurements are in centimetres.

Conventions:
- Buttons call public functions in `modNavigation` through their event property, for example `OnClick = =Nav_OpenImport()`. The only code-behind is the validation in `frmEventTypes`.
- Every child form has a **Close** button (`=Nav_CloseActive()`). It returns to the dashboard and refreshes it.
- Read-only fields are locked, skipped by Tab and shaded light grey (`#F2F2F2`).
- Colours: header `#002060`, IN `#00B050` (green), OUT `#FF0000` (red).

## frmImport: upload Excel

Single form, unbound, 20 × 13 cm.

```
+-------------------------------------------------------------+
|                    Upload Excel file                        |
+-------------------------------------------------------------+
| Excel file: [C:\...\status.xlsx                ] [Browse...]|
| File type:  [Auto  v]  Auto = detect from headers ...       |
| [ Import ]   [ Export grade totals ]             [ Close ]  |
| Result                                                      |
| +---------------------------------------------------------+ |
| | File: status.xlsx (sheet: Sheet1)                       | |
| | Rows with a waybill: 7 ...                              | |
| | This file -> IN warehouse: 2                            | |
| +---------------------------------------------------------+ |
+-------------------------------------------------------------+
```

| Control | Type | Notes |
|---|---|---|
| `txtFilePath` | TextBox | Filled by **Browse…** (`=Imp_Browse()`), but can also be typed |
| `cboImportType` | ComboBox, value list `Auto;Master;Status`, limited to the list | Defaults to `Auto` |
| `btnRun` | Button | `=Imp_Run()` |
| `btnExpGrades` | Button | `=Exp_LastMasterGrades()`: exports the per-grade quantity and loss totals of the last master file |
| `txtResult` | TextBox, locked, Consolas, vertical scroll bar | Import summary |

Validation in `Imp_Run` and `ValidateImportFile`:
- A path is required, and the file must exist.
- The extension must be `.xlsx`, `.xlsm` or `.xls`, and `~$` lock files are rejected.
- At least one sheet must contain a waybill header (`بوليصة الشحن` or `رقم التتبع`).
- **Status** requires `آخر حدث`. **Auto** fails with an explanation if the file is neither layout.

## frmShipments: inventory list

Continuous form on `qryShipmentsList`. Read-only, with no additions or deletions.

```
Header:
| Search: [__________] Show: [All v] [Search][Clear][Export IN][Export OUT][Close]
| Double-click a row to see its status history. Green = IN, red = OUT.
| Waybill | Reference | Secondary ref | Contents | Last event | Loc. | City | اسم المرسل إليه | Updated
Detail (one row per waybill):
| EBUXSL… | 71204-1   | ASR-SEP30-G9  | نقطة…    | جاهزة…     | IN   | …    | …         | …
Footer:
| Records: [=Count(*)]
```

- `txtSearch` (AfterUpdate) and `cboLocation` (`All` / `In warehouse` / `Out of warehouse`) both call `=Shp_ApplyFilter()`. The search matches waybill, reference, secondary reference, contents, consignee, city and event.
- The dashboard's **IN warehouse** and **OUT of warehouse** buttons open this form with `cboLocation` already set.
- `txtLocation` has conditional formatting: `"IN"` is bold green and `"OUT"` is bold red.
- Double-clicking any field opens `frmShipmentHistory` for that row (`=Nav_OpenHistoryForCurrent()`).

## frmShipmentHistory

Continuous and read-only, on `qryShipmentHistory`. It opens with `DetailID=<n>`.

The columns are: Waybill, From event, From (IN/OUT), To event, To, Recorded, Source file.

## frmEventTypes: event rules (IN/OUT flag read-only)

Continuous form on `qryEventTypesList`. Edits and additions are allowed, but deletions are not, because deleting an event would break the history.

The columns are **Last event** (text), **IN warehouse?** (check box, locked), **Sort** (number) and **Notes**.

The *IN warehouse?* box cannot be edited. It is ticked only for `جاهزة للالتقاط` and `استلام من العميل`, and every other event is OUT. The rule is set in `modConfig.SeedEvents` and re-applied on every status import.

- `Form_BeforeUpdate`, in the form's own module, checks three things. The name is required. The normalised `EventKey` must be unique, so the same event cannot be added twice. Sort must be numeric. It then writes the cleaned `EventName` and `EventKey`.

## frmUnmatched

Continuous and read-only, on `qryRpt_UnmatchedAll`. The columns are Batch, Imported, Waybill, Last event, City and `اسم المرسل إليه` (consignee). The **Export last batch** button calls `=Exp_Unmatched()`.

## frmGradeStock: grade stock (opens after every upload)

Continuous and read-only, on `qryRpt_GradeStock`. There is one row per grade in `tblGrades` (G1–G9, G11–G13), so grades with no items show 0.

```
Header:  [Close] [Refresh] [Export to Excel]
         Actual = Total - Loss.   Remaining in stock = Actual - OUT.
         Grade | Total Qty | Loss | Actual Qty | Total IN | Total OUT | Remaining in stock
Detail:  G1    |      3000 |  300 |       2700 |     2200 |       500 |               2200
         ...
Footer:  TOTAL |  =Sum()   | =Sum |     =Sum   |   =Sum   |    =Sum   |              =Sum
         Waybills without a valid grade (not counted): [n]
```

- Total IN is shown in green and Total OUT in red. Remaining in stock is bold, and turns red when it is below 0.
- `Imp_Run` opens or requeries this form after every successful upload, whether it was a master file or a status file.
- **Refresh** calls `=Grade_Refresh()`, and **Export to Excel** calls `=Exp_GradeStock()`.

## frmConsigneeGrades: quantity and loss by consignee and grade

Continuous and read-only, on `qryRpt_ByConsigneeGrade`. The columns are `اسم المرسل إليه`, Code, Grade, Qty, Loss, Qty IN and Qty OUT.

- A plain `G<n>` row counts 1 towards Qty. A `G<n>-L<k>` row adds k to Loss and nothing to Qty.
- **Export to Excel** (`=Exp_ConsigneeGrades()`) saves one workbook with three sheets: this list, `qryRpt_ConsigneeGradeQty` (consignees × G1–G9, G11–G13) and `qryRpt_ConsigneeGradeLoss`.

## frmImportHistory

Continuous and read-only, on `qryImportBatchesList`. The columns are Batch, Type, Imported, Read, New, Changed, Unmatched, Skipped, File IN, File OUT and File.

## Error handling

Every public procedure follows the same pattern:

```vba
On Error GoTo EH
...
ExitHere:
    Exit Function
EH:
    LogError "modX.ProcName", Err.Number, Err.Description
    Resume ExitHere
```

`LogError` adds a row to `tblErrorLog` (number, description, source, Windows user, time), prints it to the Immediate window and shows a message box. The import runs inside a DAO transaction, and any error rolls it back before logging.
